# 分支管理实践

分支是 Git 中最核心的协作机制。本文记录一套可以直接照做的分支流程，以及出现冲突时的处理办法。

## 一、为什么需要分支

如果所有改动都直接堆在 `main` 上，任何一次未完成的修改都会影响其他人拉取到的代码。分支把每个独立的改动隔离开，做完、验证通过之后再合并回主线，主线始终保持可用状态。

## 二、分支命名约定

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| feature- | 新功能 | feature-search |
| fix- | 缺陷修复 | fix-login-error |
| docs- | 文档改动 | docs-branch-guide |

统一的命名前缀可以让 `git branch` 的输出一眼看清每条分支在做什么。

## 三、创建与切换

```bash
git branch                     查看本地分支，当前分支前带星号
git branch feature-notes       创建分支但不切换
git checkout -b feature-notes  创建并立即切换到该分支
git checkout main              切回主分支
```

`git checkout -b` 等价于 `git branch` 加 `git checkout`，日常更常用这一条。

## 四、合并分支

```bash
git checkout main             先回到要接收改动的分支
git merge feature-notes       把 feature-notes 合并进来
git branch -d feature-notes   合并完成后删除该分支
```

合并的方向要看清楚：先切到目标分支，再 merge 来源分支。

## 五、冲突是怎么产生的

当两条分支修改了**同一个文件的同一处内容**，Git 无法判断该保留哪一版，就会在合并时停下并提示冲突：

```
Auto-merging notes.md
CONFLICT (content): Merge conflict in notes.md
Automatic merge failed; fix conflicts and then commit the result.
```

此时用 `git status` 可以看到该文件处于 `both modified` 状态。

## 六、解决冲突的步骤

1. 打开冲突文件，会看到如下标记：

```
<<<<<<< HEAD
当前分支的内容
=======
被合并分支的内容
>>>>>>> feature-notes
```

2. 手工编辑，保留需要的内容，删掉 `<<<<<<<`、`=======`、`>>>>>>>` 三行标记。
3. 保存后重新加入暂存区并提交：

```bash
git add notes.md
git commit -m "merge: resolve notes.md conflict"
```

4. 推送并清理分支：

```bash
git push origin main
git branch -d feature-notes
```

## 七、合并后的检查

```bash
git log --oneline --graph
```

输出中可以看到两条分支从分叉到汇合的过程，确认合并结果符合预期再结束本次操作。

## 八、几条实践经验

- 分支生命周期尽量短，做完一件事就合并、删除
- 合并前先 `git pull`，减少和他人的冲突概率
- 冲突解决后必须实际打开文件确认内容，不要只看提交是否成功
- 删除分支前用 `git branch --merged` 确认已经合并
