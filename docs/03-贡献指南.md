# 贡献指南

欢迎对本仓库提出改进。为了让协作过程清晰可控，提交前请先阅读以下约定。

## 一、参与方式

- 发现文档中的错误或遗漏，可以提 Issue 说明
- 有具体补充内容，可以 Fork 后提交 Pull Request
- 对结构有建议，先在 Issue 中讨论，达成一致后再动手改

## 二、分支规范

所有改动都不要直接提交到 `main`。请从最新的 `main` 切出分支：

```bash
git checkout main
git pull
git checkout -b docs-fix-typo
```

分支名使用 `类型-简短说明` 的格式，类型可选 `feature`、`fix`、`docs`。

## 三、提交信息规范

提交信息用一句话说明这次改动做了什么，采用英文小写开头，不加句号：

```
add stash section to command guide
fix wrong merge direction in branch doc
update readme directory tree
```

一次提交只做一件事。如果改动涉及多个主题，拆成多条提交。

## 四、文档写作要求

- 中文正文，标点使用全角
- 命令统一放进代码块，并标注语言为 bash
- 每条命令后面用一句话说明用途
- 不使用口语化表达，不使用表情符号

## 五、提交 Pull Request

1. 推送分支到自己的远程仓库
2. 在 GitHub 上发起 Pull Request，目标分支选择 `main`
3. 在描述中写清楚：改了什么、为什么改
4. 等待 review，根据意见修改后再次推送即可自动更新 PR

## 六、Issue 规范

提 Issue 时尽量包含以下信息：

- 问题出现在哪个文件、哪一节
- 当前内容是什么
- 建议改成什么

信息越具体，处理效率越高。

## 七、许可

向本仓库提交内容即表示同意以 MIT 许可证发布。
